# opc-service · 服务部技能（v1.1.1）

> 把订单和课程落成**可验收的交付**：课堂有声非空壳，交付即产生级别判据证据。
> 版本：**1.1.1** · 许可：MIT

---

## 一、它解决什么问题

交付环节的典型烂账：

- **开完课就算交付**——课表排了、班建了，学员到底学没学没人管；
- **空壳课堂**——课堂链接点进去没声音没内容，验收时才发现；
- **交付和判级脱节**——学员学到什么程度，拿不出证据，级别推进全靠嘴说。

这个技能按知识点逐条落课时与课堂，**课堂必须有音视频凭据**，交付记录直接产出级别判据证据——「可验收、出证据」是唯一标准。

## 二、它长什么样

```
opc-service（一条流水作业，不拆子技能）
├── SKILL.md            根路由 + 5 道门定义（DL-1…DL-5）
├── references/人工把关点.md   机器全包 + 必须本人事项
└── README / VERSION / CHANGELOG / LICENSE / manifest.json
```

**5 道门**（前两道需平台探活凭据）：

```
DL-1 订单有效      带审批留痕的 order.json
DL-2 课程有效      过完 PR-5 道门的 course.json
DL-3 课时落齐      逐知识点建课时，无缺漏
DL-4 课堂有声      每间课堂有音视频凭据，空壳即拒
DL-5 进度可查      进度字段可追踪、可出证据
```

## 三、怎么用

对话里直接说：

| 你想干什么 | 这样说 |
|---|---|
| 落交付 | 「这单开始交付」「按这门课建课时」 |
| 组班 | 「这批学员组个班」「挂上评价活动」 |
| 验课堂 | 「哪些课堂还是空的」「课堂有声的核一遍」 |
| 看进度 | 「这班学到哪了」「交付进度出个报告」 |

**输入**（缺一即拒）：

- `order.json` —— 销售部产出（须带审批留痕）；
- `course.json` —— 产品部产出（须过 5 道门）。

**输出**：`delivery.json` ＋ `delivery.md` ＋ `delivery-report.html`。

```json
{
  "delivery_id": "dlv-…",
  "lesson_ids": […], "class_ids": […],
  "teacher": "…", "play_urls": […], "progress": 0
}
```

## 四、安装

```bash
cp -r opc-service ~/.workbuddy/skills/     # WorkBuddy
cp -r opc-service ~/.codex/skills/         # Codex 系
```

装好后说「服务部」「开始交付」即可唤起。

## 五、机器干 ／ 人来干

**机器全包**：订单/课程有效性核验 · 课时逐条落建 · 组班与评价活动挂接 · 课堂探活核对 · 进度追踪 · 三件套输出。

**必须本人**：课堂验收放行由人抽查确认；平台探活凭据由运维提供。

## 六、硬红线

```
1  空壳课堂不过门 —— 无音视频凭据的课堂一律拒收
2  不生成课程 —— 课程是产品部的产物，本技能只消费
3  不放行结算 —— 结算是售后部的事，本技能只出交付证据
```

## 七、上下游

- **上游**：`opc-sales`（订单）＋ `opc-product`（课程）。
- **下游**：交付记录交给 `opc-aftersales`（对账结算、晋级判定）。
