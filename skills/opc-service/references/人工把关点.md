# 人工把关点（opc-service）

交付环节一半在校内、一半在平台上：平台探活与真人师资留人，其余机器管。

## 一、完全不用人操心的（机器全包）

| 事项 | 机器做到哪一步 |
|---|---|
| 硬前提核验 | `order.json` 无 `approval` 即拒 |
| 课时/课堂建单 | 按 `course.json` 知识点逐条生成建单指令 |
| 标题对账 | 课时标题＝知识点名 |
| 班级归属校验（DL-3） | 归属主体正确性 |
| 时长对账（DL-4） | 实际时长与课程基线一致 |
| 评价活动挂接校验（DL-5） | 挂接存在性与级别对应 |
| 三件套输出 | `delivery.json` ＋ `delivery.md` ＋ `delivery-report.html` |

## 二、必须本人上手的（四项，一个都不能少）

| # | 动作 | 为什么躲不掉 | 机器提前准备好什么 | 人做完回什么 |
|---|---|---|---|---|
| 1 | 讲师排班与聘用确认 | 真人师资涉及聘约与档期 | 候选讲师名单 ＋ 档期表 | 排班确认 |
| 2 | 场地与设备落实 | 线下课堂的物理条件 | 场地清单 ＋ 设备检查表 | 落实确认 |
| 3 | 平台探活凭据提供 | DL-1／DL-2 须平台接口凭据 | 探活清单（哪些课堂查什么） | 凭据或授权 |
| 4 | 课堂验收放行 | 「有声非空壳」最终由人抽查确认 | 抽查清单（按比例） | 验收留痕 |

**机器报「通过」不等于验收；验收权在人。**
