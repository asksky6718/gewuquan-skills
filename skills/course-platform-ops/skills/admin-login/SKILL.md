# 后台登录

## 用途

从「无会话」到「后台可访问」；**只到拿到管理会话为止，不代做任何后台改动。**

## 何时用

- 用户说：登录后台 / 进管理后台 / 后台打不开（表现为跳登录页或 401）
- 上游给到了：**管理口令**（从凭据保险库取）
- **取不到口令就停**：不猜、不试弱口令、不请求把口令写在对话里

## 输入

| 项 | 形态 | 从哪来 | 缺了怎么办 |
|---|---|---|---|
| 管理口令 | 密码串 | 凭据保险库（按使用者给的 code 取） | 停下，先要 code 或让使用者自行填写 |
| 管理后台地址 | URL | 固定：`https://www.课程生产工具.com/admin` | 域名变更时先确认，不要试别的域 |
| 浏览器/HTTP 客户端 | — | 使用者本机 | 说明所需，不代装 |

## 步骤

1. 打开登录页 `https://www.课程生产工具.com/admin-login`。→ 结果：登录表单渲染（未登录访问 `/admin` 会被挡）。
2. **注意表单字段语义**：登录以**管理口令**为准；页面若同时给出「管理员账号」栏，**该栏可留空/忽略**。→ 结果：只提交口令即可。
3. 提交登录：向 `POST /api/edu/v1/admin/login` 发 JSON，**鉴权体形如** `{"code":"<管理口令>"}`；或在页面上填入口令后点登录。→ 结果：成功时下发管理会话 cookie。
4. **核对成功**：带会话再次 `GET https://www.课程生产工具.com/admin` → 期望 **200**（未登录时实测为 **401**）。→ 结果：后台页面正常渲染。
5. **核对失败形态**（用于排障，不用于爆破）：错误口令实测返回 **HTTP 401**，响应体形如 `{"success":false,"errorCode":"INVALID_CREDENTIALS","error":"Invalid admin credentials"}`。→ 结果：能区分「401 未登录」与「401 凭据错误」。

## 护栏

- **不代存、不代转述、不打印口令**；产出物与对话里**只出现「已登录 / 未登录」**，不出现口令任何片段。
- **不做口令尝试/爆破**：连续两次失败即停，检查是否用错 code 或口令已轮换。
- 拿不准是哪种 401 时，统一话术：**「看响应体 `errorCode`：`INVALID_CREDENTIALS` 是口令错；空体/跳转是未登录」**。
- 会话 cookie 属凭据 → **不入产出物**；需要长期会话时由使用者自行保存。

## 产出物

- 一条登录核对结论（入口 / 登录方式 / 返回状态 / 会话可用性）—— 交使用者确认；确认后按需转其他环节。
