# 课程平台后台操作（course-platform-ops）

> 把 **课程生产工具**（互动课件生成平台）的日常操作整理成一套可照做的技能：登录后台 → 生成课件 → 发布对接 → 供应商配置 → 排障。

## 这个技能解决什么

Core 是「生成端出课件 ＋ 管理后台做发布与配置」两段式平台。日常最容易卡住的是四件事：

1. **登录语义反直觉**：登录以**管理口令**为准，页面上另有的「管理员账号」栏可以留空；
2. **生成是分次机制**：按知识点分次生成，不是一次性长篇；
3. **发布分两条通道**：发布到 OSS（静态播放） vs 同步为网校课时，选错就白做；
4. **供应商配置要过三步**：连接测试 → 保存 → 刷新回看，缺一步都不算配好。

本技能把四件事连同接口、响应形态、排障清单固化下来。

## 覆盖面

| 环节 | 内容 |
|---|---|
| 后台登录 | `/admin-login` 登录页、`POST /api/edu/v1/admin/login` 鉴权体、401 两种形态区分 |
| 生成课件 | 三段式输入、碎片化生成阶段、落库与配额口径 |
| 发布对接 | 发布到 OSS（`liveUrl`＋防盗链白名单）、网校课时同步（courseId/taskId）、iframe 嵌入 |
| 供应商与模型 | 六类能力供应商标、配置三要素、连接测试三步判定、模型/插件清单读法 |
| 排障 | 登录/生成/发布/配置四类失败的现象→处置清单 |

## 使用前你要准备什么

| 项 | 说明 |
|---|---|
| 管理口令 | 由使用者从**凭据保险库**取用；**技能不含口令** |
| 供应商 API Key | 由**使用者本人**在后台写入；技能不代填 |
| 浏览器 | 现代 Chromium 内核浏览器 |
| 目标网校/课程 | 同步课时时需 courseId；iframe 嵌入需域名先入防盗链白名单 |

## 产出样例

- **登录核对结论**：入口 / 登录方式 / 返回状态 / 会话可用性
- **课件 + 配额读数**：课堂 ID / 标题 / 阶段产物 / 本课前后的配额
- **发布结果记录**：通道 / `liveUrl` 或 `taskId` / 目标课程 / 白名单状态
- **供应商配置核对表**：能力 / 供应商 / 模型 / 连接测试 / 跨刷新留存

## 边界

- **口令与 Key 不入技能、不入产出物、不入对话**；一律从凭据保险库取、由使用者本人写入。
- **对外发布是人类门禁**：生成内容对外可见前须经负责人过目；技能只负责准备与发布到自有通道。
- **不做内容合规背书**、不做用户审核决策。
