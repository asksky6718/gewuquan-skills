# 口径来源（org-diagnose）

本技能包的口径逐条来自知识库条目的**原始标题**；`references/rules.json` 的 `evidence` 只登记本技能实际用到、且标题合规的条目，id → 原始标题逐字照录，不合成、不改写。

- 业务逻辑对齐：`portal/src/lib/workspace/diagnose.js`（五段诊断、三类方案、30 天清单与说明）。
- 出处目录对齐：`portal/src/lib/workspace/evidence.js`（条目 id → 原始标题与路径）。
- 出处纪律：引用的口径必须附条目标题；目录外的口径一律标注「本条库里没有」，不编造出处。

## 二、各条目的当前口径（诊断怎么用）

- `opc_model`（教育行业 OPC 模式）：五部门对五段流水线；上游产物是下游硬前提；涉钱环节只校验不决策。是本技能「五段」骨架的总口径。
- `opc_five`（机构经营的五段分别由谁负责、看什么门？）：受理 / 产品 / 成交 / 交付 / 结算复购五段的责任部门与各段机判、人判门；用于逐段基线与命中排序。
- `opc_pipeline`（一条完整的培训业务流水线怎么搭？）：受理 → 产品 → 成交 → 交付 → 结算复购，缺件即拒；用于交付留痕与追溯。
- `opc_channel`（招生渠道怎么设计和分账？）：渠道分级返佣、企业侧毛利梯度、价格下限与报备保护期；用于渠道分级与返佣表、线索登记。
- `opc_pricing`（培训产品怎么定价和分层？）：个人会员、课程套餐、企业与院校订阅三层产品架构；用于获客话术与分层报价口径，金额判定权在人。
- `opc_classroom`（教务怎么保证课堂不是空壳？）：交付段机判门——课堂有声、课时发布、班级归属、时长对账、评价挂接；用于课堂验收清单。
- `opc_media`（自媒体招生有哪些纪律？）：节奏 / 合规 / 转化三层纪律，AI 生成内容须披露；用于一周内容排期。
- `opc_addie`（课程设计用什么方法论？）：ADDIE 加 ISD；学习目标按认知 / 技能 / 应用三层写；用于课程拆分与知识点清单。
- `opc_product_types`（教育产品可以分成哪几类？）：技能包 / 解决方案 / 知识库调用 / 场景工具包四类；用于现有供给梳理与产品分层清单。
- `opc_scene`（教育行业场景、产品与用户类型）：按角色与是否人类两条主线划分用户，四类场景；用于机构类型的落地差异对照。

## 三、当前口径与边界

- 本技能只给建议动作，不承诺经营结果；结论按现行口径测算，以机构实际与属地政策核定为准。
- 机构类型与规模只影响说明层提示（`scale_notes` 与机构类型差异条目），不改变五段诊断与三类方案的骨架。
- 具体经营数据、财务与属地合规口径不在库内（见 `rules.json` 的 `uncovered`），须以机构实际与主管部门要求为准。
- 口径更新：改 `rules.json` 即改输出；每次更新须升版本并同步 `CHANGELOG.md`，且以知识库原始标题的最新口径为准。
