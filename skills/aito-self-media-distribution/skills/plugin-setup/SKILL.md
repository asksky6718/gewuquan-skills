# 插件就绪

## 用途

把「一台干净的浏览器」变成「控制台认可的已就绪插件环境」；**只到「插件 已就绪」为止，不代登录任何平台账号。**

## 何时用

- 用户说：插件没装 / 插件未就绪 / 发布没反应 / 装了还是提示未就绪
- 上游给到了：**实例域名**（部署地址）
- **缺域名就停**：先问清是哪套实例，不要拿别的地址试

## 输入

| 项 | 形态 | 从哪来 | 缺了怎么办 |
|---|---|---|---|
| 实例域名 | URL | 用户 / 部署方 | 停下，先要域名 |
| 扩展包（CRX 或已解包目录） | 文件/目录 | 控制台插件引导页，或项目仓库 | 停下，先拿包；不得从不明来源下载 |
| 浏览器 | Chromium（带固定 profile 与远程调试端口） | 使用者本机 | 说明所需启动参数，由使用者启动 |
| 目标平台登录态 | 人工扫码一次 | 使用者在插件打开的平台页内完成 | 停下，等人工登录；**不代登录** |

## 步骤

1. **取包**：从本实例控制台插件引导页（路径形如 `/zh-CN/websit/plugin-guide`）取得扩展包。→ 可检查结果：拿到 CRX 文件或已解包目录。
2. **解包**（若拿到的是 CRX）：CRX ＝ 带签名的 ZIP；**去掉文件头的 CRX 段后按 ZIP 解压**，得到扩展目录。→ 结果：目录里有 `manifest.json`，且 `manifest_version` 为 3。
3. **以固定 profile 启动浏览器并开调试端口**，参数：`--remote-debugging-port=<端口>`、`--user-data-dir=<本机 profile 目录>`、`--load-extension=<解包目录>`。→ 结果：`http://127.0.0.1:<端口>/json/version` 可读。
4. **加载扩展**：`chrome://extensions` → 打开「开发者模式」→「加载已解压的扩展程序」→ 选解包目录。→ 结果：扩展卡片出现，版本号与包内 `manifest.json` 一致。
5. **加域允许（关键）**：把**实例域名**与目标平台创作域加入扩展允许注入列表（至少：实例域名、小红书创作者中心域、微信视频号平台域、B站创作中心域）。→ 结果：允许列表里能看到这些域。
6. **授 cookies 权限**：给扩展授予 cookies 权限，否则读不到目标平台登录态。→ 结果：扩展权限页显示已授权。
7. **验证扩展侧无报错**：`chrome://extensions` 无「错误」徽标。→ 结果：扩展卡片正常态。
8. **人工登录一次目标平台**：在扩展打开的平台页内扫码登录；登录态随 profile 持久。→ 结果：平台页显示已登录。
9. **回控制台确认就绪**：控制台侧栏扩展状态项显示「**浏览器插件 已就绪**」。→ 结果：该状态项为就绪态。

## 护栏

- **不代使用者登录其平台账号**，不索取平台口令与验证码。
- **不从不明来源下载扩展包**；包只从本实例控制台引导页或项目官方仓库取。
- 拿不准是否装对时，统一话术：**「按包内 `manifest.json` 的版本号与控制台显示比对，一致才算装对」**。
- 覆盖浏览器 profile 属不可逆动作 → **先备份 profile 目录**再动。

## 产出物

- 一份「插件就绪核对表」（域名 / 扩展版本 / 域允许 / cookies / 就绪状态）—— 交使用者确认；确认后转 `skills/account-bind/SKILL.md`。
