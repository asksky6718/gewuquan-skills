# 账号绑定

## 用途

把目标平台账号挂到实例控制台上，并**用只读接口**确认每条账号真的可用（`status=1`）；**不代填口令、不代点授权。**

## 何时用

- 用户说：绑定账号 / 加频道 / 账号状态 / 发现 N 个账号有问题
- 上游给到了：**插件已就绪** ＋ 侧栏能看到扩展状态为就绪
- 插件未就绪就停：先转 `skills/plugin-setup/SKILL.md`

## 输入

| 项 | 形态 | 从哪来 | 缺了怎么办 |
|---|---|---|---|
| 实例域名 | URL | 用户 / 部署方 | 停下先要 |
| 插件就绪状态 | 控制台状态项 | 上一步产出 | 未就绪则回插件就绪环节 |
| 目标平台账号 | 人工授权 | 使用者在平台侧完成 | 停下等人工授权 |
| 只读接口凭据 | 控制台页面上下文里的 token | 从控制台页取（见 `references/api-readonly.md`） | 取不到就用控制台 UI 目测，并在产出物标注「未接口核对」 |

## 步骤

1. 打开控制台发布页（路径形如 `/accounts`）→ 右上角加号「添加账号」。→ 结果：平台选择列表出现。
2. 选目标平台 → 按插件引导完成授权（人工在平台页确认）。→ 结果：控制台账号列表新增一条。
3. **接口核对**：`GET <实例域名>/api/v2/channels/accounts`（带 `Authorization: Bearer <token>`）→ 逐条读 `status` / `fansCount` / `type`。→ 结果：拿到账号清单原始 JSON。
4. 逐条判定：`status=1` ＝ 有效；否则按 `references/api-readonly.md` 的字段说明定位。→ 结果：每账号标注「有效／待处理」。
5. 若控制台提示「**发现 N 个账号存在问题**」：先读**问题原文**——多数是**内容要求未满足**（如"请上传视频""标题是必须的""必须选择分区"），**不是授权失效**。→ 结果：区分「内容要求」与「授权失效」两类。

## 护栏

- **不代填平台口令、不代点授权、不代过验证码**；授权一律由使用者在平台页完成。
- **不把 token 写进产出物或对话**；只报「读到的状态值」。
- 拿不准账号是否有效时，统一话术：**「以只读接口 `status` 字段为准，控制台的提示文案不等于授权失效」**。
- 账号解绑/注销属不可逆动作 → **由使用者自行在平台侧操作**，技能只做核对。

## 产出物

- 一份「账号状态核对表」（平台 / 账号标识 / `status` / 判定）—— 交使用者确认；有效账号转 `skills/publish/SKILL.md`，异常项转 `skills/troubleshoot/SKILL.md`。
