# 排障核对

## 用途

把「一个具体现象」变成「一条可复现的处置结论」；**只报事实与实跑结果，不猜根因。**

## 何时用

- 用户说：点了没反应 / 报错 / 排期不生效 / 上传失败 / 按钮点不动
- 上游给到了：**现象原话** ＋ 当前步骤（哪一步、填了什么）
- **缺现象原话就停**：先问清「点了什么、期待什么、实际什么」，不猜

## 输入

| 项 | 形态 | 从哪来 | 缺了怎么办 |
|---|---|---|---|
| 现象原话 | 文本 | 用户 | 停下先问 |
| 复现步骤 | 文本 | 用户 / 现场 | 停下先问 |
| 实例域名 ＋ 只读凭据 | URL ＋ token | 用户 / 控制台页 | 取不到就只做 UI 侧判断并标注 |
| 原始输出（console / 网络面板 / 截图） | 文本/图 | 用户 | 停下先要；**不看原始输出不下结论** |

## 步骤

1. 对照清单初步归口（见下表）→ 结果：得到候选处置项（可多项）。
2. 逐项实跑验证：**每项都做到「改了之后现象是否消失」有结论**。→ 结果：每项标注「已消／未消／不适用」。
3. 需要接口判定的走只读调用（见 `references/api-readonly.md`）→ 结果：拿到原始 JSON 片段。
4. 仍无法归口时，**如实记「未复现/未归口」**，给出下一步取证要求（要哪些原始输出）。→ 结果：一条不含猜测的结论。

| 现象 | 处置 |
|---|---|
| 点击被 `fixed inset-0` 遮罩拦住 | 关掉「未完成的发布记录」提示（见 `skills/publish/SKILL.md` 步骤 2） |
| 普通 `click` 账号/按钮无效 | 改 `.click(force=True)` |
| `set_input_files` 报 single file | 账号未选中（input 仍为单选）→ 先选对账号 |
| 「发布」点击无任何请求 | 多账号冲突（含视频类账号）→ 只留一个图文账号 |
| 关闭按钮点不动 | 用 JS 直点 `button`（文本为 Close/完成/关闭）或按 `Escape` |
| 误点背景日历导致选择器关闭 | 定时日期只在**选择器内**的 `[role=dialog]` 里点 |
| 控制台提示插件未就绪 | 回 `skills/plugin-setup/SKILL.md` 查域允许与 cookies 权限 |
| 排期确认后仍按立即发布 | **已知限制**，见 `references/pitfalls.md` |

## 护栏

- **只报事实**：不给根因猜测，不在未复现时给"应该是…"的结论。
- **不动生产数据**：不做服务端写操作、不改数据库、不批量重发。
- 拿不准时统一话术：**「未复现，需要原始输出（console / 网络面板 / 截图）才能归口」**。
- 反复重试同一步属无效动作 → 连续两次失败即停，转人工。

## 产出物

- 一份「现象—处置—实跑结果」三段式记录 —— 交使用者确认；涉及产品或平台缺陷时，转需求/缺陷登记。
