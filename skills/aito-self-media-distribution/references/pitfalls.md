# 三条硬纪律与坑（实测沉淀）

## 一、一次只选一个账号

账号头像项是可多选的。

- 选中态判据：`className` 含已选标记（`--publish-account-platform-border`）；含 `border-transparent` ＝ 未选。
- 若同时选了「需要视频」的账号（视频号/B站）而只给了图文，**「发布」按钮静默无响应**（无报错、无请求）。
- ⇒ 发布前**逐账号单选**；切换用 `click(force=True)`（普通 `click` 可能被遮挡）。

## 二、「定时发布」不生效（实测）

在定时选择器内选定未来时间并确认（触发按钮已显示该时间），点「发布」后：
**记录里的 `publishTime` 仍是当前时刻** ⇒ 插件按「立即发布」执行。

**绕法**：需要真排期时，**不要依赖控制台的排期**——由外部任务在目标时间点触发发布，或人工到点再发。

## 三、「保存草稿」只在本地

在对话框里保存草稿：**无任何 API 调用**，草稿仅存浏览器 `localStorage`（该 profile 内可见，**不落服务端、换机即失**）。

⇒ 在控制台上「登记计划」只能落两种形态：**① 直接发布** 或 **② 本地草稿**；**没有服务端排期登记**。

## 四、其它常见坑

| 坑 | 处置 |
|---|---|
| 遮罩拦截点击 | 关掉「未完成的发布记录」提示（精确匹配「不恢复」） |
| 上传按钮不弹文件选择器 | 用媒体输入控件直接 `set_input_files`，不要点上传按钮 |
| 上传报 single file | 账号未选中 → 先选对账号 |
| 误点背景日历导致定时选择器关闭 | 只在选择器内的 `[role=dialog]` 里点日期 |
| 关闭按钮点不动 | JS 直点 `button` 或按 `Escape` |
| 提示「发现 N 个账号存在问题」 | 多数是**内容要求未满足**，非授权失效 |

## 五、纪律

1. **对外可见内容先经负责人过目**再发；技能不代他人发布。
2. **一条主线一套口径**：多账号/多主线内容**不得串用**，发布前做隔离自检。
3. **凭据只进凭据保险库**，不入技能正文、不入产出物、不入对话。
