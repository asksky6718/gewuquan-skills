# 业绩提炼

## 用途

把客户嘴里"我做过一个系统"改写成评委会看得懂的申报语言，并**核对角色与佐证是否对得上**。

## 何时用

- "这个项目怎么写进材料"；
- "我的工作内容该怎么描述"；
- 项目参与情况证明要出草稿时。

## 输入

```
项目名称 / 立项单位 / 建设周期
本人角色（负责人 / 主要参与人 / 参与人）
技术方案与用到的技术栈
本人具体干了什么 / 解决了什么技术难题
可提供的佐证：立项任务书、合同、验收报告、获奖证书
```

## 步骤

1. **先盘家底**：一个人手上有几个项目？目标评委会要几项？（如数字技术第三要业绩成果 **2 项以上**，且要跨类别满足）——先数够不够；
2. **按骨架填**（每项目一页）：

```
项目名称   | 立项单位 | 姓名 | 参与项目角色（☐负责人 ☐主要参与人 ☐参与人）
项目简介   ：项目定位 / 核心功能 / 技术栈
个人工作内容：本人在项目中的角色、承担的具体工作、解决的技术难题
单位证明意见："情况属实，特此证明" + 单位盖章 + 负责人签章 + 日期
备注       ：附项目原始文件和相关项目证明材料
```

3. **写"个人工作内容"三段法**：
   - 定位：我在这个项目里是什么角色、管什么；
   - 动作：我具体做了哪几件事（用动词，要有技术含量）；
   - 结果：解决了什么难题、带来了什么可验证的结果；
4. **核对一致性**：勾了"负责人"必须有对应佐证（任命/合同/验收）；勾"参与人"却写得像负责人，会被质疑；
5. **标注缺件**：需要但客户还没提供的佐证，列出来催。

## 护栏

- **不虚构项目、不夸大角色**——评委会会核；
- 不得写"国际先进""国内领先"这类**主观结论**（系统填报明确禁止）；
- 项目必须**已完成**，且与系统"项目/课题情况"栏描述一致；
- 项目（工程）设计说明书、产品说明书、可行性研究、立项申请、验收报告、测试报告、产品标准、专利申请报告**不能替代**项目技术总结；
- 专利必须是**已授权**的，受理/公示中的不算。

## 产出物

- 每人每项目的**项目参与情况证明草稿**；
- 一份**佐证缺件清单**（催客户补）。
