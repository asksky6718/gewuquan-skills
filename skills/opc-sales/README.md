# opc-sales · 销售部技能（v1.1.1）

> 把线索和课程转成**带审批留痕的订单**：只核资质与审批，不定价、不承诺。
> 版本：**1.1.1** · 许可：MIT

---

## 一、它解决什么问题

招生成交环节最容易出事的三处：

- **口头答应**——销售在聊天软件里承诺了「包过」「不过退款」，事后没人认账；
- **乱报价**——折扣随手打，账期随手给，公司根本不知道这单卖给了谁什么价；
- **资质悬空**——客户机构连办学许可都没有就签单，后面全是退费纠纷。

这个技能把成交收敛成一张机器可核的订单：资质齐不齐、合同编号有没有、报价审批留没留痕——**三道门全过才算成交**。价格判定权永远在人，机器只核「审没审过」。

## 二、它长什么样

```
opc-sales（单一流程，不拆子技能）
├── SKILL.md            根路由 + 三道门定义（DE-1/2/3）
├── references/人工把关点.md   6 项机器全包 + 5 项必须本人
└── README / VERSION / CHANGELOG / LICENSE / manifest.json
```

**三道门**：

```
DE-1 资质齐备     办学许可 / ICP / 证书等级逐项核对
DE-2 合同编号     存在性与格式
DE-3 审批留痕     approval_channel / approval_by / approval_at 三项齐全
```

## 三、怎么用

对话里直接说：

| 你想干什么 | 这样说 |
|---|---|
| 起一单 | 「张三那家机构建个订单」「这单能不能成」 |
| 核资质 | 「这单资质齐不齐」「办学许可过期没有」 |
| 核合同 | 「合同编号给了吗」 |
| 登记审批 | 「报价走完审批了，登记一下」 |
| 看话术 | 「这个级别的产品用什么话术」 |

**输入**（缺一即拒）：

- `lead.json` —— 市场部产出（线索，带级别标签）；
- `course.json` —— 产品部产出（课程，带目标级别）。

**输出**：`order.json`（含审批留痕三件）＋ `order.md` ＋ `order-report.html`。

```json
{
  "order_id": "order-20261009-001",
  "approval_channel": "offline_recorded_admin",
  "approval_by": "…", "approval_at": "2026-10-09T15:00:00"
}
```

## 五、机器干 ／ 人来干

**机器全包 6 项**：上游两件齐备核验 · 话术匹配（按产品分级 B1–J1）· 资质校验 · 合同编号校验 · 审批留痕核验 · 三件套输出。

**必须本人 5 项**：报价／折扣／账期审批 · 审批录入 · 合同盖章签署 · 资质原件核验 · 对外承诺（交付期／效果口径）。

**没有审批留痕的订单，机器拒收——这是本技能最硬的一道门。**

## 六、硬红线

```
1  不自动定价 —— 折扣与报价只核「是否已审批」，金额判定权在人
2  不做对外承诺 —— 效果口径、交付期承诺一律留人审批
3  无留痕不落库 —— approval 三件不齐即拒
4  复印件不算核验通过 —— 资质以原件为准
```
