# opc-sales · 销售部

> **保密级别：内部件 · 禁止对外发布**（技能生产总纲定级）。

## 定位与边界

| | 内容 |
|---|---|
| **本 skill 干什么** | `lead.json` ＋ `course.json` → `order.json`（订单/项目） |
| **上游（硬前提）** | **必须**同时给 `lead.json` 与 `course.json`，缺任一即拒 |
| **下游** | `opc-service`（服务部）吃 `order.json` |
| **不做** | 🔴 **不定价、不给折扣、不承诺**——只校验 `approval` 是否存在（涉钱涉对外一律留人逐次放行） |

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| `lead.json` | 是 | 上游市场部产物 |
| `course.json` | 是 | 上游产品部产物 |
| 产品目录 | 是 | 主体产品线全景（认证培训／就业服务／企业服务／政府国企培训／竞赛／职称评审／教育科技产品） |
| 价格政策 | 是 | 引用主体库现行口径（**共享库只放指针**） |
| `approval` | 是 | 审批记录（建议复用平台凭据三档的 **admin 档**） |

## 工作流

### Step 1 — 选话术
按产品分级（主体产品线 B1–J1 体系）取对应材料：

| 级别 | 产品类别 |
|---|---|
| B1 | 人工智能标准化服务 |
| C1 / C2 | AI 转型咨询与陪跑 / 能耗管理系统 |
| **D1 / D2** | **人工智能培训产品（核心）** / 人才赋能服务 |
| E1 / E2 / E3 | 知产 / 算法大模型备案 / 企业融资服务 |
| F1 | 会员服务产品（协会） |
| J1 | 数智化技术开发服务 |

每个产品配 **「销售话术」＋「一指禅」** 两套材料（见主体话术库）。

### Step 2 — 报价与审批（**人的环节**；2026-10-02 已拍板：线下批＋平台 admin 档录入并留痕）

> 🔴 本步**不由本 skill 决定价格**。skill 只做两件事：
> ① 检查 `approval` 字段存在且合规；② **核验它的来源可追溯**。
> 保留线下审批的业务习惯，但**必须由 admin 档录入**，否则 `approval` 会退化成一句无法验证的自述。

`approval` 必须带三项留痕：

| 字段 | 说明 |
|---|---|
| `approval_channel` | 固定为 `offline_recorded_admin`（线下批、admin 档录入） |
| `approval_by` | 录入人/审批人标识（须为平台 admin 档有效身份） |
| `approval_at` | 审批时间（ISO-8601） |

金额、折扣、账期仍由人放行。**未审批、或审批无留痕的订单不得落库。**

### Step 3 — 生成 `order.json`
字段：`order_id` · `buyer` · `subject` · `amount` · `qualification` · `contract_no` · **`approval`** ·
**`approval_channel`** · **`approval_by`** · **`approval_at`**
合同文本复用主体合同模板库。

### Step 4 — 校验 ⛔ 不能跳

| 门 | 查什么 | 判门 |
|---|---|---|
| DE-1 | 资质齐备（办学许可／ICP／证书等级；办学主体须持办学许可证） | 🟢 机判 |
| DE-2 | 合同编号存在且格式合法 | 🟢 机判 |
| **DE-3** | **`approval` 存在 ＋ 三项留痕齐全**（`approval_channel=offline_recorded_admin`、`approval_by`、`approval_at`） | 🔴 **人判**（金额正确性不在本 skill 职责内） |

> 校验器由装配层统一下发（与全流水线同一套实施待办，本版不内置命令位）。

### Step 5 — 输出
`order.json` ＋ `order.md` ＋ `order-report.html`（三件套）

## 红线
1. **不自动定价**；2. **无 `approval` 不得落库**；3. 对外报价只出现当前主体口径。

## 能力总览

| 能力 | 做什么 | 入口 |
|---|---|---|
| **订单受理** | 线索＋课程 → 带审批留痕的订单，3 道门校验 | 本文件（简单技能，不拆子技能） |

## 路由判定表

| 用户这样说 | 前置门禁 | 进入 | 明确不要做 |
|---|---|---|---|
| 「订单建一下」「资质齐不齐」「合同编号给了吗」 | 上游 `lead.json` ＋ `course.json` 齐备 | 本文件工作流 | 不定价、不承诺 |
| 「打个折」「便宜点」 | — | **停**：走线下审批，人拍板 | 本 skill 不自动定价 |

## 通则

- 上游产物是硬前提：缺件即拒，不代补。
- 审批留痕三项缺一不可；无留痕的订单不得落库。
- 交付末块统一：回复末块标题一律「交付后请确认」。

## 环境与约定

- 纯文档流程：本版不内置校验命令；校验器由装配层统一下发。
- 价格政策只在主体库，共享库只放指针。

```
□ approval 三项留痕齐全（渠道／审批人／时间）
□ 对外口径只出现当前主体名
```
