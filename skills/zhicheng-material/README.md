# 申报材料助手（zhicheng-material）

> 选**目标等级**、**申报通道**与**当前身份** → 得到一份逐项带**知识库出处**、材料要求、出具方与办理地点的申报材料清单 ＋ **缺件提示** ＋ 可复制的**逐项生成指令**。
> 只出准备清单，**不代提交、不代签字、不代盖章**，清单末页固定标**须本人核对**。
> 版本：**1.0.0** · 许可：MIT · 权限档：`read`

---

## 一、它解决什么问题

申报「要交什么、谁出、去哪办」分散在评价机构公告、属地口径与知识库条目里，逐项手工核对既慢又容易漏。本技能把这件事拆成三步：

1. **拼清单**：公共基础材料 ＋ 目标等级对应的逐级申报材料 ＋ 所选通道的专属材料。
2. **标出处与去向**：每一项都给材料要求、出具方、办理地点，并挂知识库**原始条目标题**；知识库未单列的通用受理要件，如实标注「本条库里没有」，不编造出处。
3. **算缺口给指令**：对照「已具备材料」勾选，列出待准备项，并为每一项生成一段可复制的草稿指令。

## 二、它长什么样

```
输入：level（等级） + channel（通道） + status（身份） + known（已具备材料，可多选）
   │
   ├─ 拼装：7 条公共基础项 + 等级专属项 + 通道专属项（三级/四级/五级另附可选补贴项）
   ├─ 逐项：材料要求 / 出具方 / 办理地点 / 知识库出处
   ├─ 对照 known：标记「已具备 / 待准备」，输出待准备项
   └─ 逐项生成指令（可复制）+ 4 条声明 + 2 条说明
```

示例入参：

```json
{ "level": "level3", "channel": "social", "status": "employed", "known": ["education", "work"] }
```

清单构成：

| 分区 | 条数 | 内容 |
|---|---|---|
| 公共基础项 | 7 | 身份证明、学历 / 学籍证明、工作年限证明、已有职业技能等级证书、已有职称证书（如有）、业绩 / 成果材料、申报表与个人承诺 |
| 等级专属项 | 0–1 | 二级 / 技师与一级 / 高级技师：下一级职业技能等级证书；三级 / 高级工：初级职称证明（走职称对应路径时） |
| 通道专属项 | 1–2 | 社会培训评价组织：机构资质核验记录 ＋ 当期评价计划与缴费凭证；用人单位自主评价 / 技工院校：各 1 条 |
| 补贴项（可选） | 0–1 | 目标等级为三级 / 四级 / 五级时附技能提升补贴申领材料 |

## 三、怎么用

在支持本技能引擎的工作台里选中「申报材料助手」，填好 `level` / `channel` / `status`（`known` 按实际勾选）即可；或直接对智能体说：

- 「帮我列一份职业技能等级申报材料清单。」
- 「报三级 / 高级工要交哪些材料？」
- 「走社会培训评价组织通道，我还缺什么？」
- 「技能提升补贴申领需要哪些材料？」

## 四、边界（务必先读）

- **不代提交／不代签字／不代盖章**；清单末页固定标**须本人核对**。
- 本清单只作材料准备参考，**不构成报名受理、资格认定或通过承诺**。
- 能否报、报哪一级，以及补贴金额与时限，**以评价机构与属地人社部门当期核定为准**。
- 只出材料清单与生成指令，**不给承诺话术**。
- 知识库未单列的口径，只标注「本条库里没有」，**不编造出处**。
- 只读、不联网、不写文件。

## 五、文件清单

```
zhicheng-material/
├── SKILL.md                 # 唯一事实源（frontmatter + 七段正文）
├── VERSION                  # 1.0.0
├── CHANGELOG.md
├── README.md
├── LICENSE                  # MIT
└── references/
    ├── engine.json          # {"engine":"material","rules":"rules.json"}
    ├── rules.json           # 业务规则唯一事实源（fields / items / evidence / notes）
    ├── 口径来源.md           # 逐条出处与知识库原始条目标题对应
    └── 人工把关点.md         # 机器不代办的步骤
```

## 六、改规则怎么改

- 清单项、等级 / 通道 / 身份取值、出处与说明**只改** `references/rules.json`；改内容即升版本，同步改 `VERSION` 与 `CHANGELOG.md`。
- `engine.json` 的 `rules` 只能是 `references/` 下的文件名，不得带路径分隔符或 `..`。
- 清单项 `key` 与 `fields` 里 `known` 可勾选项一一对应；等级专属项与补贴项由引擎按所填等级自动带出。
