# opc-product · 产品部

> **保密级别：内部件 · 禁止对外发布**（技能生产总纲定级）。

## 定位与边界

| | 内容 |
|---|---|
| **本 skill 干什么** | `lead.json` ＋ `ladder.json` → `course.json` |
| **上游（硬前提）** | `lead.json`（含 `opc_level` 目标级别）；**必须给标尺**（装配层注入，本包不内置，避免双源） |
| **下游** | `opc-sales`（定价标的）与 `opc-service`（交付依据）|
| **不做** | 不生成课堂实体（课堂系统的活）；不排班（服务部的活） |

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| `lead.json` | 是 | 上游市场部产物，含 `opc_level` |
| `opc-ladder.json` | 是 | OPC 九级标尺（装配层注入；每级的课程绑定与判据） |
| 教学大纲/题库 | 考试类必填 | 已批准大纲；考试类必须提供题库 |

## 工作流

### Step 1 — 定目标级别与课程绑定
从标尺取该级的 `course_binding`，确定课程主题与时长预算。

### Step 2 — 拆知识点（铁律一）
**1 个知识点 ＝ 1 个课堂 ＝ 1 个课时**，每知识点 ≈5 分钟。
- 禁止一次性生成长课时；
- 一门课由 10+ 个短课时组成。

### Step 3 — 大纲验证（铁律二）
每个知识点输出：名称 · 学习目标 · 要点 · **大纲出处** · 题库考点（考试类）· 目标时长 · 互动设计。
- 逐条标注出处，**覆盖度 100%**；
- 不确定处标 `needs_source`，**禁止编造**。

### Step 4 — 题库绑定（铁律三 · 考试类强制）
按「题库模块 × 题型 → 考点 → 知识点」建映射，**课程不得脱离题库**。

### Step 5 — 生成 `course.json`
字段：`course_id` · `target_opc_level` · `knowledge_points` · `duration_min` · `question_bank_binding` · `delivery_mode`

### Step 6 — 校验 ⛔ 不能跳

| 门 | 查什么 | 判门 |
|---|---|---|
| PR-1 | 知识点碎片化：每知识点 ≤5 分钟且 1:1:1 对应课堂/课时 | 🟢 |
| PR-2 | 大纲验证：逐条有出处、覆盖 100%、`needs_source` 数量在阈值内 | 🟢 |
| PR-3 | 题库绑定：考点↔知识点映射齐全（考试类） | 🟢 |
| PR-4 | 课时标题 ＝ 知识点名 | 🟢 |
| PR-5 | 累计时长在目标总量 ±10% 内 | 🟢 |

> 校验器由装配层统一下发（与全流水线同一套实施待办，本版不内置命令位）。

### Step 7 — 输出
`course.json` ＋ `course.md` ＋ `course-report.html`（三件套）

| 用户这样说 | 前置门禁 | 进入 | 明确不要做 |

| 「直接出一门 2 小时的课」 | — | **停**：违反知识点碎片化铁律 | 拒绝长课时 |

## 通则

- 1 知识点＝1 课堂＝1 课时（≈5 分钟）；一门课由 10+ 短课时组成。
- 大纲逐条有出处；不确定标 `needs_source`，禁止编造。
- 未经人确认的大纲不得进入下游。
- 交付末块统一：回复末块标题一律「交付后请确认」。

## 环境与约定

- 标尺由装配层运行时注入（`--ladder`），本包不内置，避免双源。
- 本版不内置校验命令；校验器由装配层统一下发。

## 执行前核对

```
□ lead.json 含目标级别，标尺已注入
□ 考试类课程已备题库
□ 大纲确认人已明确
```
