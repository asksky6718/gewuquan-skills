# opc-product · 产品部技能（v1.1.1）

> 按**九级标尺**产课程：知识点碎片化、大纲逐条有出处、考试类必须绑题库——三门强校验，宁可让人裁决十条，不让机器编造一条。
> 版本：**1.1.1** · 许可：MIT

---

## 一、它解决什么问题

课程生产的老毛病：

- **拍脑袋排课**——大纲凭经验写，讲完才发现漏了考点；
- **知识点塞太满**——一节课讲 40 分钟的干货，学员根本消化不了；
- **出处说不清**——内容是抄的还是核过的，没人对得上原文；
- **考试课没题库**——说好「应试培训」，考题和讲课内容两张皮。

这个技能把课程拆成**知识点颗粒**（1 知识点＝1 课堂＝1 课时，约 5 分钟），每条大纲必须有出处，考试类课程强制绑定题库——机器核形状，人核内容对错。

## 二、它长什么样

```
opc-product（一条流水作业，不拆子技能）
├── SKILL.md            根路由 + 5 道门定义（PR-1…PR-5）
├── references/人工把关点.md   6 项机器全包 + 4 项必须本人
└── README / VERSION / CHANGELOG / LICENSE / manifest.json
```

**5 道门**：

```
PR-1 碎片化       每知识点 ≤5 分钟，1:1:1 对应
PR-2 大纲出处     逐条有出处、覆盖 100%、不确定处标 needs_source
PR-3 题库绑定     考点↔知识点映射齐全（考试类强制）
PR-4 标题一致     课时标题＝知识点名
PR-5 时长对账     累计时长偏差 ±10% 以内
```

## 三、怎么用

对话里直接说：

| 你想干什么 | 这样说 |
|---|---|
| 产一门课 | 「给 L2 级别产一门课」「按这条线索的目标级别排课」 |
| 拆知识点 | 「把这章拆成知识点」 |
| 验大纲 | 「大纲验证一遍」「哪几条还没出处」 |
| 绑题库 | 「考试类课程绑题库」「考点对不上的列出来」 |
| 对时长 | 「总课时和承诺的对得上吗」 |

**输入**：

- `lead.json`（含目标级别）—— 市场部产出；
- 九级标尺（L1–L9 能力定义）—— 由装配层注入，不随包内置。

**输出**：`course.json` ＋ `course.md` ＋ `course-report.html`。

```json
{
  "course_id": "course-…", "target_opc_level": "L2",
  "knowledge_points": [
    { "name": "…", "duration_min": 5, "outline_ref": "…" }
  ],
  "question_bank_binding": { … }
}
```

## 五、机器干 ／ 人来干

**机器全包 6 项**：知识点碎片化 · 大纲出处校验 · 题库绑定校验 · 课时标题一致 · 时长对账 · 三件套输出。

**必须本人 4 项**：**大纲确认放行（硬闸口，未确认不得进下游）** · 题库授权与版权确认 · 师资聘约与资质 · `needs_source` 项逐条裁决。

## 六、硬红线

```
1  大纲必须经人确认 —— 未经确认的大纲禁止流入生产
2  不确定不编造 —— 找不到出处一律标 needs_source，禁止现编
3  考试类必绑题库 —— 考点与知识点对不上即拒
4  不生成课堂实体、不排班 —— 那是服务部的活
```
