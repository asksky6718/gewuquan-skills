## 三、机械核对程序测试（本轮核心）

**被测件**：`scripts/gap_check.py`（v2.1）
**测试方式**：**正向回归（两份真实工作簿）＋ 反向对照（合成含缺陷表）**。只跑正向会漏掉缺陷——空模板表对任何检查逻辑都返回「0 阻断」，掩盖了「首行数据被吃」这类错误。
**测试纪律**：全程只读，不改用户文件；脚本不联网、不自动装依赖。

### 3.1 正向回归：两份真实工作簿

| 用例 | 命令要点 | 结果摘要 | 退出码 |
|---|---|---|---|
| **A · 单表推进表** | `--xlsx "…教培体系建设推进表.xlsx" --region 上海` | 共 1 张表；识别「优化版」**21 行**；判**空模板**；阻断 0 / 重要 0 / 建议 0 / 提示 0 | **0** |
| **B · 多表测算总表** | `--xlsx "…资质项目测算总表（模板）.xlsx" --region 上海` | 共 6 张表；识别「工作截点」**22 行**（**季度列 15 个 → 判矩阵**）；其余 5 表判非推进表跳过；判**空模板**；全部 0 | **0** |
| **C · 指定非推进表** | 同上 ＋ `--sheet 服务报价` | **拒答**：不做任何缺失判定，列出各表真实表头 | **3** |
| **D · 表头侦察** | 同上 ＋ `--show-headers` | 打印每张表识别到的表头行、命中列、被跳过表的实际表头 | **0** |

**A 的原始判定片段**（照抄）
```
- 识别的表：「优化版」(21 行)
- 数据结构：**空模板**（尚无时间/状态/责任人）
- 结论：阻断 0 / 重要 0 / 建议 0 / 提示 0
## 说明
- 「优化版」另有一处疑似表头在第 2 行（命中 8），本次按第 1 行核
```

**B 的原始判定片段**（照抄）
```
- 工作表：共 6 张；识别为推进表 1 张，跳过 5 张
- 识别的表：「工作截点」(22 行)
- 跳过的表（非推进表）：「基础数据」、「人员成本」、「资金使用」、「服务说明」、「服务报价」
- 数据结构：**空模板**（尚无时间/状态/责任人）
- 结论：阻断 0 / 重要 0 / 建议 0 / 提示 0
## 说明
- 「工作截点」是按季度横向铺开的**计划矩阵**（季度列 15 个）：按「分类/子项目/责任人/到位时间」核，不对季度格逐格判日期。
```

**多 sheet 核验结论**（对应验收要求「资质项目含多个 sheet，须仔细核验」）
- 6 张表**逐张判定**，不出现「只读第一张」；
- 5 张非推进表（基础数据／人员成本／资金使用／服务说明／服务报价）**正确跳过**，且跳过原因可查（`--show-headers` 会显示它们的最佳命中为 **0**，低于阈值 3）；
- 唯一推进表「工作截点」的**真实表头是第 2＋3 行合并**（r2 = 分类/母项目/子项目/达成目标/责任人/到位时间 ＋「第一年」；r3 = 第一季度、第二季度……），程序正确按两行复合表头拼接，数据自第 4 行起读；
- 表 B 的**季度矩阵**（横向 15 个季度列）被识别为矩阵表，**不逐格判日期**（否则会刷出上百条假日期错误）。

### 3.2 反向对照：合成含缺陷表（防止「一律返回 0」的摆设）

**造法**：合成一张 8 列 × 4 数据行的推进表，故意埋入 4 类缺陷：

| 埋入的缺陷 | 期望能否抓到 |
|---|---|
| 非法日期 `2026-15` | 能 |
| 合法月粒度节点 `2026-11` | **不该**被抓（正常写法） |
| 状态标「已完成」但备注含「待核」 | 能 |
| 完全缺「场地／消防」类任务 | 能 |

**实测结果**：退出码 **1**；**阻断 2 / 重要 12 / 建议 1 / 提示 0**。抓到：缺场地、缺消防（阻断）；缺章程、缺师资、缺验资、缺设备、缺收费公示、缺培训协议、缺台账、缺年检、缺评价资质、字段空值、`2026-15` 非法日期、状态与备注矛盾（重要）；缺「验收标准」列（建议）。**`2026-11` 未被误报。**

### 3.3 本轮由反向对照发现并修掉的 4 个残留缺陷

| # | 缺陷 | 现象 | 根因 | 修复 | 修复后实测 |
|---|---|---|---|---|---|
| 1 | **首行数据被吃掉** | 4 行表只认 3 行；表内明明有「名称核准」任务却报「缺少名称核准」；`2026-15` 非法日期漏抓 | `collect_rows()` 固定从「表头行 +2」起读（为兼容两行复合表头写的），**单行表头时多跳一行** | 表头类型随候选一起返回，数据起点按 `+1`（单行）／`+2`（复合）取 | 行数 **3 → 4**；「缺少名称核准」消失；`2026-15` 被抓到 |
| 2 | **月粒度节点被判非法** | `2026-11`、`2026年11月` 报「无法解析」＋「非法日期片段」 | 正则只认 `YYYY-MM-DD`；且二次匹配把 `2026-12` 当成 `2026-12-01` 的前缀重复计数 | 改为**一次扫片段再分类**（日=0 表示只到月）；顺序核对按月初／月末折算 | `2026-11` 不再报错，`2026-15` 仍报错 |
| 3 | **状态白名单过窄** | 正常的「未开始」被判「状态越界」 | 白名单仅 5 个词 | 扩到 24 个常见状态词，并去掉「越界即重要」的过强判定 | 「未开始」不再报错 |
| 4 | **缺列噪声** | 表里根本没有「验收标准」列，却**逐行**报缺失 | 逐行必查 4 个字段，不先看该列是否存在 | 整列缺失**只报一次**；列存在才逐行查空值 | 3 条刷屏 → 1 条 |

> 另外去掉一处重复：同一格的非法日期原先同时报「无法解析」和「非法日期片段」两条，现在只报片段级一条。

### 3.4 v1.1.0 → v2.1 对照（同一批输入）

| 用例 | v1.1.0 | v2.1 |
|---|---|---|
| A 单表推进表 | **任务行数 0** ＋ 假阻断 **7 条** | 识别 21 行，判空模板，**0 findings** |
| B 多表测算总表 | **任务行数 0** ＋ 假阻断 **7 条** | 识别「工作截点」22 行（矩阵），5 表跳过，**0 findings** |
| C 指定非推进表 | 假阻断 **7 条** | **拒答 ＋ 退出码 3** |
| E 反向对照 | — | **抓到 2 阻断 / 12 重要 / 1 建议** |

**结论**：v1.1.0 的致命问题是「**认不出表 → 当成表里什么都没有 → 报 7 条阻断**」，属最坏的一种错误（把工具的局限说成用户的缺陷）。v2.1 用**拒答（退出码 3）**根治，并补上反向对照证明它并非「一律返回 0」。

**退出码约定**：`0` 无阻断 ｜ `1` 存在阻断 ｜ `2` 文件/依赖问题 ｜ `3` 拒答（未识别到可核对的表）

## 四、执行主线的可操作性验证（v2.0.0 新增内容）

`references/执行主线.md` 的两条主线（A 新办机构八门／B 新设职业工种五门）逐门对照真实流程走了一遍，核对点：
