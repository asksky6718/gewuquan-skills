# 脱敏案例 · 一套实际提交的职业（工种）申报材料

> **案例说明**
> - 来源：一套**实际报送**的民办职业培训学校「新增职业（工种）」申报材料，申报时间 **2025 年 5 月**，事项属地为中国上海市。
> - 脱敏处理：主体名、客户名、地名、门牌、人名、身份证号、手机号、第三方机构名**全部替换为中性泛称或删除**；内容结构、材料种类、字段栏目、阈值指标**保持原样**。
> - 本案例**只说明"一份完整的申报包长什么样"**，不代表审批结果，也不构成对任何属地要求的背书。**拿它当清单用，不当标准用。**

> **观察一**：这份案例走的是「**逐等级成套**」路线——申请表按等级分张、设置标准按等级分册、教学文件按等级分份。等级越多，工作量近似**成倍**。
> **观察二**：真实包里**扫描件占比很高**（教师证件、产权、租赁合同都是扫描）。装订与命名规范比内容更容易丢分。

## 三、逐份实录（字段与结构）

### 3.1 申请报告（1 份）

抬头：**<属地区>人力资源和社会保障局**。正文按七栏：

1. **办学宗旨**：遵守法律法规与教育方针，培养<职业>专业人才，提高从业人员专业技能。
2. **培养目标**：以该职业技能培训为主导，兼顾在职培训、岗前训练、再就业培训。
3. **办学规模**：首年计划培训约 200 人。
4. **举办者概况**：机构名称 / 办学地址与邮编 / 联系电话 / 法定代表人 / 校长 / 举办者（公司或个人）。
5. **办学形式**：面授。
6. **拟增设职业（工种）及培训层次**：<职业>（五级）、<职业>（四级）、<职业>（三级）。
7. **招生对象**：计算机/软件相关专业学生或从业人员、数据分析师、算法工程师、企业在职职工、转行人员、自由职业人员等。

文末：申请单位（人）＋日期。

> **坑（本案例实际存在）**：报告开头用了一段**产业政策引用＋市场数据**（例如「职位需求同比增长 XXX%」）。这类数字**必须标原始出处**；本案例的该数字未标出处，**本技能不转发、也不建议任何人照抄**。

### 3.2 职业（工种）申请表（每等级一张）

**封面**：申请单位（加盖公章）/ 职业（工种）/ 培训等级 / 申请日期；页脚「<属地>人力资源和社会保障局印制」。

**填表说明**（原文要点）：本表**一式三份**（一份留申请单位、两份留审批机关备案，其中一份报上级机关）；**每个培训专业每个等级分别填报一张表格**；封面编号为 8 位数（前 2 位审批年份、3–4 位月、5–6 位日、7–8 位年度审批序号）；可加附页；电子文档可从属地人社官网下载。

**表体四块**：

| 块 | 实际字段 |
|---|---|
| 培训单位基本情况 | 申请单位 / 所属区县 / 单位地址 / 邮政编码 / 联系电话 |
| 拟设职业的培训场地及设施设备情况 | 教室（间）/ 实习场地（面积）/ 出租单位 / 场地地址 / 租赁起止期限 / **设施设备清单：名称＋型号＋适用等级** |
| 拟设职业的师资情况 | 持教师资格证书人数 / 兼职人数 / 持聘用合同的兼职人数；**理论课、实习课教师逐人一行**：任课课程名称、职称、教师资格任教学科、联系电话、编制所在单位及担任职务 |
| 承诺与审批意见 | 申请单位承诺（真实性负责）＋印章＋日期；人社部门审批意见＋印章＋日期 |

> **观察三**：师资表里的**「课程名称」直接对应教学计划的模块名**（如通识、业务分析、智能训练、智能系统设计）——教学计划、申请表、教师材料三处的课程名必须**对得上**，这是最容易被挑前后矛盾的地方。

### 3.3 教学文件（三件套）

**（1）职业设置标准**——属地下发的《<职业>培训机构职业设置条件（试行）》，4 页，内容即`application-package-recipe.md`第三节那张「门槛表」。本案例该标准的关键阈值：

- 按 **30 人/班**制定，原则上**不超过 50 人/班**；超员须相应增配教师与设备；
- 专业理论课教师 **≥3 人**、实训指导教师 **≥3 人**，两者**可兼用**；
- 从教资格**二选一**：人社/教育部门核发的教师资格（上岗）证，**或**企业兼职讲师有 3 年以上本行业经历；
- 从业经历：院校/培训机构相关课程教学 2 年以上，或相关企业技术岗 3 年以上；
- 理论教室 **30 座以上**＋多媒体＋局域网＋百兆带宽；实操场地能满足 **30 人以上**同时实训；
- 设备按角色定下限：CPU 服务器全校 ≥3 台、GPU 服务器全校 ≥2 台、教师机每教室 1 台、学生机每教室 ≥30 台，逐项列 CPU/内存/硬盘/网卡参数；
- 软件：支持数据获取与标注实训；支持 Jupyter Notebook 与 TensorFlow / PyTorch；
- 必备教学资料：《<职业>国家职业技能标准》＋配套培训教材；
- 环境：教室人均面积、供电照明、消防通风符合国家标准。

**（2）教学计划 + （3）教学大纲与教材**（每等级一份，同一模板）：

- 课程基本信息：课程名称 / 培训等级 / **总课时（理论＋实操，另计考核课时）** / 适用对象 / 培训目标；
- **课程模块与课时分配表**：课程类型（理论课/实操课）× 课程名称 × 课时 × 教学形式；
- **教学大纲**：逐模块写「教学目标 / 教学内容（分课时）/ 实训项目」；模块名与申请表的课程名称一致；
- **考核方案**；
- **拟使用教材**：主教材（国家职业资格培训教程）＋辅助材料（公开出版物）。

> **观察四**：教学计划里给的示例课时是「40 课时（理论 8 ＋ 实操 32）＋考核 4 课时」。**课时数不是自由写的**——要与属地要求的培训学时口径对齐，报之前必须回属地确认。

### 3.4 教师材料（每位教师七件）

| 件号 | 材料 | 本案例的实际形态 |
|---|---|---|
| 4-1 | 培训教师简历 | 含出生年月、学历（含在读）、所学专业、职业等级及发证日期、所在单位、联系电话、通讯地址、邮编、承担教学职业/等级 |
| 4-2 | 个人承诺书 | 同一文件内（4-1＋4-2 常合为一份） |
| 4-3 | 学历（学位）证书 | 扫描件 / PDF |
| 4-4 | 教师资格证 / 上岗证 | 扫描件 |
| 4-5 | 职业资格 / 技术等级 / 聘任证 | 可多份（如信息安全师、高级多媒体作品制作员、副教授/教授聘任证、数据分析师、通信专业技术人员职业资格） |
| 4-6 | 身份证 | 扫描件 |
| 4-7 | 聘用（兼职）合同 | 与举办者签订，固定期限（本案例为 **2 年**）、按课时计酬、一式两份双签 |

**师资构成（本案例 5 人）**：3 名来自院校（含教授、副教授级）＋ 2 名来自企业/培训机构，**全部为兼职**；理论课与实习课教师存在**兼用**。

**兼职合同要点（实录）**：聘用方（举办者）／受聘方／工作岗位与地点（"在该校从事兼职讲师工作"）／固定期限／工作时间不固定／**按次计酬**（本案例 70 元/课时）／每月固定发薪日／保密义务／合同变更、解除、终止情形／双签生效、一式两份。

> **观察五**：`4-1 简历` 里的「所在单位」与 `4-7 合同` 的「聘用方」**不是同一家**——简历写的是教师人事关系所在单位，合同写的是举办者。两处不一致容易被问，**准备时先想好怎么解释**。

### 3.5 场地证明（三种）

| 材料 | 本案例形态 | 要点 |
|---|---|---|
| 产证复印件 | 6 页扫描件 | 自有产权证明 |
| 房租租赁合同 | 7 页扫描件 | **合同期限须覆盖办学周期**（本案例为 5 年期） |
| 无偿使用证明 | 1 页扫描件 | 他人无偿提供时，由产权方出具 |

> **观察六**：本案例中申请表填的「出租单位」是**两名自然人**。也就是说自有/租赁/无偿三种可以**并存**，按实际先用哪个填哪个；关键是**合同期限与办学周期对得上**。

## 四、这套材料告诉我们什么（可复用经验）

1. **等级成倍放大工作量**：一次性报三个等级，申请表、设置标准、教学文件都要三套。定价与排期时按「等级数」乘。
2. **三处课程名必须一致**：教学计划的模块名 ＝ 申请表的课程名称 ＝ 教师承担教学科目。不一致是最常见的退回原因。
3. **师资是硬门槛**：人数（理论 ≥3、实训 ≥3）与资格（教师资格证 或 3 年企业经历）两条都要过；院校教师与企业讲师混编能同时满足「资格」与「经历」两类要求。
4. **设备要有清单且标等级**：不是"有电脑就行"，要逐条列名称、型号、适用等级，并达到最低配置下限。
5. **扫描件是主要失分点**：证件、产权、合同多盖章多签名，清晰度与方向、命名规范比想象中重要。
6. **市场数据要有出处**：报告里的产业数据一旦无出处，整份材料的可信度会被连带质疑。
7. **属地标准是唯一标尺**：本案例的阈值（30 人/班、3 台服务器……）只属于**该属地该职业该年份**。换属地、换职业、换年份都要重新取当期标准。

## 五、本技能从本案例里提取的规则

- 「设置标准是门槛表，逐条对照」→ 写入 `application-package-recipe.md` 第三节；
- 「市场数据须标出处」「属地标准是唯一标尺」→ 写入根 `SKILL.md` 通则与 `skills/scope-route/` 护栏。
