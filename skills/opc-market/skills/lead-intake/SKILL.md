# lead-intake · 线索受理

## 用途

触点事件 → `lead.json`（线索），并打 OPC 级别标签（L1–L9），使**招生分级与能力分级共用一把尺子**。含招生转化鱼塘模型的「鱼苗」层：个性归户、学员信息管理、渠道归因。

## 何时用

- 「这条私信／活动名单怎么登记成线索」——触点归集。
- 「给这批线索分级」——打标（有证据自动、无证据挂人工）。
- 「线索校验一遍」「为什么这条线索被拒」——5 道门校验与拒因解释。

## 输入

| 输入 | 必填 | 说明 |
|---|---|---|
| 触点事件 | 是 | 自媒体互动／品牌活动／渠道合作／协会活动／会员服务／学员推荐 |
| 主体信息 | 是 | 机构名或学员身份（`subject`） |
| 联系方式 | 是 | 手机号或邮箱（只入主体库） |
| 需求描述 | 是 | `need` |
| 主体名册 | 是 | `--registry` 注入的 JSON（IN-2 校验用） |
| OPC 标尺 | 条件 | `--ladder` 注入；定级判据查询用（本包不内置） |

## 步骤

1. **归集**（鱼塘三层）：**鱼苗**——个性归户（分级别、消费能力、渠道来源、从事行业；分群：课程类别、学员风格）；**打鱼**——精准营销动作（日常问候／挽留／课程升级）；**养鱼**——自媒体与社群运营（内容获客、企微运营、裂变、学习型组织）。
2. **打标**（按证据分流，2026-10-02 已拍板）：
   - **有证据** ⇒ 依据证据定级，记 `opc_level_source="auto_with_evidence"` 并附 `evidence_ref`。L1：题库测评分数达标＋概念覆盖度；L2–L4：已提交并通过结构校验的产物／方案／工作流定义。
   - **无证据** ⇒ **不猜**：`opc_level` 留空，`pending_level_review=true`，`opc_level_source="human"`，转人工。
   - **人工定级** ⇒ 记 `opc_level_source="human"` 并附 `level_by`。
   - ⚠️ 门只能校验「级别**有出处**」，校验不了「标得对不对」——所以「无证据不许自动填」写在本步骤行为里。
3. **生成 `lead.json`**：字段契约见 `references/lead-fields.md`。
4. **校验 ⛔ 不能跳**：

   ```bash
   python tools/lead_check.py validate <lead.json> --registry <主体名册.json>
   ```

   IN-1 渠道归因完整 ｜ IN-2 主体合法 ｜ IN-3 联系方式格式 ｜ IN-4 幂等去重 ｜ IN-5 级别有出处。**不过不放行。**
5. **输出三件套**：`lead.json`（机器）＋ `lead.md`（人）＋ `lead-report.html`（装配层拼装）。

## 护栏

- 联系方式属个人信息：**只入主体库，不入共享库正文**。
- 对外材料只出现当前主体名。
- 上游无触点事件则拒（本 skill 是流水线起点，不接收上游产物）。
- 自测：`python tools/selftest.py`（不调模型、不花额度；每道门都有击穿用例）。

## 产出物

`lead.json` ＋ `lead.md`（＋装配层拼装的 `lead-report.html`）；下游 `opc-sales` 以 `lead.json` 为硬前提。
